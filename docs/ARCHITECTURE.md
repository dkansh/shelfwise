# Shelfwise architecture

_Last updated: early 2026_

## Overview

Shelfwise is a single Spring Boot application (a "modular monolith") exposing a REST
API. There's no frontend in this repo; the web client lives in a separate project.

```
   client ──HTTP──▶  [ JwtAuthenticationFilter ]
                              │
                     [ Controllers ]  ── validation, mapping
                              │
                       [ Services ]   ── business rules, transactions
                         │       │
              [ Repositories ]  [ ApplicationEventPublisher ] ──▶ listeners
                         │
                    [ H2 / Postgres ]
```

## Layers

- **Controllers** only deal with HTTP. They call one service and return a DTO.
  No business logic in controllers.
- **Services** hold all business rules. All services use constructor injection.
- **Repositories** are Spring Data JPA interfaces. Complex searches use Specifications
  (`repository/spec`).
- **DTOs** are Java records. Entities are never returned from the API.

## Packages

Most code is organised by layer (`controller`, `service`, `repository`, ...). Newer
modules are organised by feature instead:

- `fines` - fines and payments
- `events` - library events (book clubs, readings)

The plan is to move everything to feature packages eventually.

## Security

Stateless JWT authentication. `AuthController` issues tokens, `JwtAuthenticationFilter`
validates them on every request. Roles are `ADMIN`, `LIBRARIAN` and `MEMBER`.
ADMIN can do everything a LIBRARIAN can.

URL-level rules live in `SecurityConfig`; finer rules use `@PreAuthorize` on the
controllers.

## Domain events

Loan activity publishes Spring application events (`event` package):

| Event               | Published by            | Listeners                                   |
|---------------------|-------------------------|---------------------------------------------|
| `LoanCreatedEvent`  | `LoanService.checkout`  | `AuditEventListener`                        |
| `BookReturnedEvent` | `LoanService.returnBook`| `ReservationEventListener`, `AuditEventListener` |

All listeners run asynchronously so they can't slow down or break the main request.

## Database

- Dev: in-memory H2, schema generated by Hibernate (`ddl-auto: update`).
- Prod: PostgreSQL. Schema changes are managed with Flyway migrations in
  `src/main/resources/db/migration`.

## Caching

Spring cache with a simple in-memory cache manager. Cached:

- `books` - single book lookups
- `categoryTree` - the category tree

Caches are evicted whenever the underlying data changes.

## Scheduled jobs

| Job                          | When            |
|------------------------------|-----------------|
| `OverdueLoanScheduler`       | 02:00 daily     |
| `ReservationExpiryScheduler` | hourly          |
| `MembershipExpiryScheduler`  | 08:00 daily     |

Enabled with `shelfwise.scheduling.enabled=true`.

## Notifications

`NotificationService` writes an in-app notification and sends an email through an
`EmailSender`. In dev the `LoggingEmailSender` just logs the email; in prod
`SmtpEmailSender` is used. Email bodies come from text templates in
`resources/email-templates`.
